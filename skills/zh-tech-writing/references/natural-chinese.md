# 自然中文的改写示例

检查翻译腔、空泛修饰和连续否定时参考。判断以整句含义和使用场景为准，改写后核对操作、状态、数量和条件。

## “真实”等词怎样改

本项目偏好具体、平实的表述。仅用于加强语气的“真实”“真正”“实际”“有效”等修饰语，通常可以删去。需要表达差别时，直接说明差在哪里。

这些词出现在句中，本身不能说明文字由机器翻译生成。检查时看它是否提供了读者需要的信息，以及意思能否从原文或项目资料中确认。

| 场景 | 原写法 | 改写 |
| --- | --- | --- |
| 图像来源已写明，“真实”只是强调 | 使用相机采集的真实图像 | 使用相机采集的图像 |
| 明确比较机器人与仿真 | 在真实机器人上运行，与仿真结果比较 | 在真机上运行，与仿真结果比较 |
| 只需说明本次运行的输出 | 查看本次程序运行的真实输出 | 查看本次程序运行的输出 |
| “真正”只用于强调保存动作 | 将录制的视频真正保存到本地 | 将录制的视频保存到本地 |
| 只有空泛的效果评价 | 本节有效地帮助你理解推理流程 | 本节介绍推理流程 |
| 内容是配置说明 | 保留技术事实 | 保留原文的功能说明、参数和操作要求 |
| 内容是日志中的报错 | 日志提供了程序无法打开 `config.yaml` 的证据 | 日志显示，程序无法打开 `config.yaml` |

“真实数据”可能指采集数据、生产数据或未经修改的数据。按上下文确认含义后选词；来源不明时，保留已知内容，并在影响任务要求时向用户确认。“实际”“真正”“实测”也按句意使用，尤其“实测”需要有测量过程。

已有术语按原义使用，例如虚拟现实、实时推理和数据真实性。字段、函数和产品名称沿用项目写法，如 `ground_truth`、`realpath` 和 Unreal Engine。

## 其他容易照搬英文的写法

以下均为本项目示例，用于说明改写方法。

| 需要检查的写法 | 原句 | 改写 |
| --- | --- | --- |
| 把动作写成“进行 + 名词” | 对配置文件进行修改 | 修改配置文件 |
| “拥有……的能力” | 这个函数拥有读取图像的能力 | 这个函数能读取图像 |
| “这允许你……” | 这个按钮允许你导出视频 | 点击这个按钮可导出视频 |
| 重复主语或所属关系 | 你可以在你的输出目录中查看你的结果 | 在输出目录中查看结果 |
| 名词前堆叠多个修饰语 | 检查由相机在本次运行中所采集到的图像 | 检查相机在本次运行中采集的图像 |
| 不必要的“层面” | 在文件层面对配置进行修改 | 修改配置文件 |

“允许”表达权限、“有效”描述校验结果、“实际值”与“目标值”相对时，都有具体含义。此类用词按技术含义保留。

## 说明句中的疑问式表达

遇到英文 `explain what…`、`describe how…` 等表达，先判断句子要交代的内容，再按中文习惯组织。说明对象、方法、原理或原因时，选择自然的动词搭配；指示读者操作时，直接写具体动作。

以下为本项目的改写示例，原写法用于提示检查，不代表所有类似句子都需要改写。

| 场景 | 原写法 | 改写 |
| --- | --- | --- |
| 说明待确认的内容 | 资料不足时，保留已有信息，并说明还需确认什么。 | 资料不足时，保留已有信息，列出待确认的内容。 |
| 说明资料缺口和核实方法 | 说明缺少什么、如何确认。 | 列出缺失的信息，并说明核实方法。 |
| 介绍工作原理 | 解释这个模块如何工作。 | 说明这个模块的工作原理。 |
| 介绍运行流程 | 本节解释这个模块如何工作。 | 本节介绍这个模块的运行流程。 |
| 分析连接失败的原因 | 说明为什么连接失败。 | 说明连接失败的原因。 |
| 写操作指导 | 说明读者要做什么、做到什么程度。 | 写清具体做法和完成标准。 |

“如何工作”可能指工作原理或运行流程，“如何确认”也可能指核对资料或向他人确认，具体译法以语境为准。

按整句含义选词，避免把“什么”一律换成“哪些事项”，或把“如何”一律换成“相关方式”。有具体对象时，直接写出对象；原文未给出具体信息时，标出待确认的内容，保留原有的不确定性。

疑问词在提问、问题标题和口语中可以自然使用，例如“如何配置代理？”“不确定就说清楚哪里不确定、怎么验证。”检查重点是句子是否自然、含义是否清楚。

## 把连续否定改成具体做法

普通说明围绕读者要完成的事展开，写清动作、结果和必要条件。同一段出现多个“不要”“避免”“不能”时，检查它们是否能合成一条明确要求。

| 原写法 | 改写 | 保留的要求 |
| --- | --- | --- |
| 不要遗漏报错，不要省略执行命令，不要漏掉 Python 版本。 | 报告问题时，附上完整报错、执行命令和 Python 版本。 | 三项信息齐全 |
| 不要修改已有函数，不要更改参数名，不要删去检查代码，只填写标记区域。 | 保留已有函数、参数名和检查代码，仅在标记区域填写答案。 | 修改范围仍限于标记区域 |
| 不要把 `config.yaml` 放在其他目录。 | 将 `config.yaml` 放在当前工作目录。 | 假定前文已经指定当前工作目录 |
| 没有删除权限的用户，不能删除此文件。 | 用户必须有删除权限，才能删除此文件。 | 删除权限是必要条件 |
| 结果尚未保存时，不得关闭程序。 | 关闭程序前必须保存结果。 | 保存后才可关闭 |

“更新固件期间禁止断电”应保留明确禁令。“装置未接通电源”“测试未通过”等状态按原意表述。权限、前提和禁止事项的含义保持一致，措辞强度与原文一致。
