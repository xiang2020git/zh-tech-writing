# 中文技术文档写作

目标：写出像资深工程师写的中文技术文档。**平实**、**具体**、**短句**。

## 流程

**写新文档：**

1. 明确读者是谁，读完要能做成什么事。已有信息足够时直接写；影响内容取舍的关键信息缺失时，向用户询问。
2. 按下面的“句子”“语气”“段落与结构”“排版”写。
3. 对照“AI 腔清单”检查全文，结合前后文修改不合适的表述。
4. 跑 `autocorrect --fix <文件>`，修空格和标点。命令不存在就跳过，改为按“排版”手动检查。
5. 手动检查 autocorrect 管不到的：引号、省略号、破折号。

**修改已有文档：**

1. 修改前通读全文。
2. 用户只要意见：保留文件原样，按“原句 → 改后 → 原因”列出问题。
3. 否则直接修改文件，并按上面的第 3～5 步完成检查。交付时用两三句话说明主要改动。

完成各项检查，修改发现的问题。引用原文和展示反例的句子按用途保留。

## 句子

- 用逗号隔开的每一截，尽量在 20 字以内。超过 30 字就拆开。整句不超过 100 字。
- 一句只说一个意思。多用简单句和并列句，把长定语拆出去。
  - 差：那个昨天生病的人没有参加会议。
  - 好：他昨天生病了，没有参加会议。
- 普通说明以肯定句为主，直接写做法和完成条件。双重否定改成明确的要求或状态。安全禁令、权限限制和判断条件保留原意。
  - 差：不能不检查输出目录。 → 好：检查输出目录。
  - 状态说明：请确认装置未接通电源。
  - 差：没有删除权限的用户，不能删除此文件。 → 好：用户必须有删除权限，才能删除此文件。
- 能说明谁在做什么时，直接写明。少用多余的“被”字句。
  - 差：假如此软件尚未被安装 → 好：假如还没安装这个软件
- 操作说明按动作之间的关系组织。并列的操作分别说明。某一步用到前一步的结果时，指出要用的结果。较长的流程用编号步骤。
  - 遇到套用“先……，再……”的句子，重写整句，保留操作顺序、判断条件和字段或数组元素的顺序。改写重点是说明动作或数据的关系；“首先”“然后”“随后”同样按句意使用。
  - 差：每对夹指先放换算得到的位置，再放它的相反数。
  - 好：每对夹指的两项依次为换算后的位置和该位置的相反数。
- 直接用动词表达动作。
  - 差：对配置文件进行修改 → 好：修改配置文件
- 说明和操作要求中，留意照搬英文疑问从句的写法，如“说明还需确认什么”。按句意写成自然的动作和对象，必要时拆句。
  - 差：并说明还需确认什么。 → 好：并列出待确认的内容。
  - 介绍工作原理时：解释这个模块如何工作。 → 说明这个模块的工作原理。
  - “什么”“如何”等词按整句判断。提问、问题标题和自然的口语表达可以保留，避免一律换成“哪些事项”“相关方式”等空泛说法。
- “这”“其”“该”只指一个明确的对象。可能有歧义就把名词重复一遍。
- 名词前的修饰语不超过两层，多了就拆成两句。
- 用现代汉语常用词。
  - 差：这是唯二的方法。 → 好：只有这两种方法。
- 分清“的、地、得”：开心的笑容、开心地笑、笑得开心。

## 语气

- 像给同事讲清楚一件事，使用读者熟悉的日常表达。
- 称呼读者用“你”，称呼项目方用“我们”。
- 用陈述语气，句末用句号。
- 说明具体功能、操作或测试结果。数字、命令、文件名和报错内容以原文或项目资料为准。缺少会影响结论的信息时，列出缺失的信息，并说明核实方法。
  - 差：p99 延迟从 120 ms 降到 40 ms，性能得到了大幅提升。
  - 好：p99 延迟从 120 ms 降到 40 ms。
- 确定的事直接说。不确定就说清楚哪里不确定、怎么验证。
- 写清具体做法、完成标准和问题处理方法。连续出现“不要……”“避免……”时，改成具体做法，合并重复提醒。明确的要求和禁令按原意表述，保留适用条件和原有语气强度。
  - 差：不要遗漏报错，不要省略执行命令，不要漏掉 Python 版本。
  - 好：报告问题时，附上完整报错、执行命令和 Python 版本。
  - 必要禁令：更新固件期间禁止断电。

## 用词

- 写清对象、动作和结果。概括词指代不明时，按原文说明具体内容。
- “事实”“证据”“依据”等概括词按文意展开。说明功能时写功能，说明测试时写测试结果，说明判断从哪里来时写日志、文档或数据。
- 本项目偏好具体表述。“真实”“真正”“实际”等词仅用于强调时，删去修饰语；需要区分对象时，写明真机与仿真、采集数据与生成数据等具体差别。所写的差别应能从原文或项目资料中确认。
- 按整句话的意思改写，来源、数字、原因和条件沿用原文。术语和名称按项目约定使用，例如虚拟现实、实时推理、数据真实性、`realpath` 和 `ground_truth`。
- 函数名、字段名、产品名和已有术语保留原名。技术上的“依赖”“输入输出”“上下文窗口”等，按实际含义使用。

下面的例子说明句子怎么改：

| 原写法 | 按文意改写 |
| --- | --- |
| 保留技术事实 | 保留原文的功能说明、参数和操作要求 |
| 用事实代替形容词 | 写清具体功能或已有的测试结果 |
| 日志提供了程序无法打开 `config.yaml` 的证据 | 日志显示，程序无法打开 `config.yaml` |
| 保留依赖关系 | 后一步用到前一步的结果时，指出要用的结果 |
| 保留数据排列 | 保留字段和数组元素的顺序 |
| 全文没有命中上述写法 | 全文未发现上述写法 |
| 使用相机采集的真实图像 | 使用相机采集的图像 |
| 在真实机器人上运行，与仿真结果比较 | 在真机上运行，与仿真结果比较 |

表中“依赖关系”的例子指操作步骤。软件包依赖、函数调用等场景仍用相应术语。

检查翻译腔、空泛强调或连续否定时，读 [references/natural-chinese.md](references/natural-chinese.md)。其中列出网上指南的例子，以及本项目的改写示例。“真实”等词结合整句判断；本项目的措辞偏好与外部指南分别说明。

## 段落与结构

- 每段第一句写重点，后面的句子补充说明。一段只讲一个主题。
- 一段最好不超过 4 行，最多 7 行。
- 标题用二级、三级为主：
  - 标题按一级、二级、三级逐层安排。
  - 同级标题只有一个时，去掉这层标题。
  - 下级标题说明本节内容。
  - 需要四级标题时，改用 `**（1）xxx**` 或列表。
  - 标题写成简短短语，末尾省略句号、逗号、冒号。
- 并列、可以单独扫读的条目用列表。有因果、转折关系的内容，写成段落。
- 加粗只给读者必须注意的警告或关键词，一屏最多一两处。
- 引用别人的内容或图片，注明出处。

## 排版

每篇都要守的规则：

- 中文与英文、数字之间加一个半角空格：`在 Linux 上安装 5 个包`。
- 中文句子用全角标点：`，。：；？（）`。整句是英文时用半角标点。
- 英文、数字后面紧跟全角标点时，中间不加空格：`他用的是 MacBook Air。`
- 引号用全角 `“ ”`，引号里再套引号用 `‘ ’`。
- 并列的词用顿号 `、` 隔开，最后一项用“和”连接：`Google、腾讯和百度`。
- 省略号写成 `……`，不写 `...` 或 `。。。`，也不和“等”连用。
- 数字一律用半角。

数字（千分位、单位、范围、倍数）、括号、冒号、连接号、英文缩写的细则，见 [references/typography.md](references/typography.md)。文档里出现这些内容时读它。

写一整套产品手册或文档站、需要规划目录和文件名时，读 [references/manual-structure.md](references/manual-structure.md)。

## AI 腔清单

自检时逐条对照。左边是要找的写法，右边是改法。

| 找这种写法 | 改成 |
|---|---|
| 开场套话：“随着……的发展”“在当今……”“值得注意的是”“需要指出的是”“让我们来看看”“接下来我们将介绍” | 删掉，第一句直接说内容 |
| 结尾套话：“总的来说”“综上所述”“总而言之”，或重复前文的总结段 | 删掉。确实需要结尾，只写新信息，比如下一步做什么 |
| 客套话：“希望对你有帮助”“如有问题欢迎交流” | 删掉 |
| 只为加强语气的对比句式：“不是 A，而是 B”“与其说 A，不如说 B” | 直接说明重点；需要澄清的技术区别和误解保留 |
| 递进句式：“不仅……而且/更……” | 拆成两个陈述句 |
| 操作说明套用“先……，再……”“首先……然后……” | 按“句子”中的规则改写。用到前一步的结果时，写明要用的内容，保留原有条件和顺序 |
| 硬凑三个：三个排比形容词、每组都是三项的列表 | 有几项写几项 |
| 设问自答：“关键是什么？答案很简单：”“原因很简单：” | 直接给结论 |
| 宣传腔形容词：强大、灵活、无缝、全面、极致、优雅、轻松、一站式 | 写清具体功能或已有测试结果；只有空泛评价时，删去评价 |
| 黑话：赋能、抓手、闭环、链路、沉淀、对齐、颗粒度、维度、底层逻辑、范式、打通 | 换成白话。代码或业务里的正式名称（如“调用链路”）保留 |
| 破折号 `——` 用来插入解释 | 改用逗号、冒号、括号，或拆成两句。全文最多一两处 |
| 翻译腔：“进行 + 动词”“通过……的方式”“作为一个……”、一句里多个“的” | 直接用动词，拆开长定语 |
| 说明句生硬地套用“说明……什么”“解释……如何……” | 按“句子”中的规则，用自然的搭配写清内容、方法、原理或原因；提问和自然的口语表达按用途保留 |
| 用“事实”“证据”等词笼统概括各种信息 | 按“用词”中的例子写清具体内容，避免固定词语替换 |
| “真实”“真正”“实际”“有效”等修饰语只起强调作用 | 删去空泛强调；需要区分来源、设备或状态时，按资料写明区别，保留已有术语 |
| 连续用“不要”“避免”“不能”组织普通说明 | 写清具体做法和完成条件，合并重复提醒；必要禁令和技术限制保留原意 |
| 过度含糊：“在某种程度上”“在一定情况下可能会” | 确定就直接说；不确定就说清条件 |
| 感叹号、emoji 标题或列表符号 | 句号，纯文字标题 |
| 每段都加粗、一两句话也拆成列表、小标题比段落还密 | 按“段落与结构”重排 |
